# Compiler vs interpreter, 2026-09-17

Every package fn was pushed through the x64 compiler; every one that compiled was run
both ways on synthesized inputs and the results diffed byte for byte. Every fn is in
`2026-09-17d-functions.csv`.

## Numbers

    package fns                        5,138
    compile                            3,242   63%
      provable (inputs synthesizable)  2,124
      identical output                 2,116   99.6%
      differ or crash                     23

The 1,118 compiled-but-unprovable fns take a function or a custom-typed value the
synthesizer can't build, or are effectful. Nothing is known about their correctness yet.

## The 23 that compile and are wrong

Differ (8):

- `Cli.Packages.Search.sortKey`: an interpolated `if`-valued string comes out empty
  (`0:...` vs `01:...`)
- `LanguageTools.NameResolver.namesToTry`: nested `List<List<String>>` escaping differs
- `WIP.AI.Anthropic.Chat.Request.withUserMessage`, `WIP.AI.OpenAI.Chat.withAssistantToolCalls`,
  `WIP.AI.OpenAI.Chat.withToolResult`, `WIP.AI.OpenAI.Responses.getResponseId`,
  `Stachu.JsonCanvas.Json.edgeToJson`: the compiled binary prints nothing. All take a
  large synthesized record; hand-built inputs match, so the synthesizer is suspect.
- `CompilerCases.Stdlib.Int64.shiftLeft_byWidth`: deliberate. `1y << 8y` is 1 interpreted
  (masked shift count) and 0 compiled.

`Stachu.JsonCanvas.Json.canvasToJson`, `Stachu.JsonCanvas.Server.indexHandler`,
`Stachu.JsonCanvas.Server.router`. All build JSON from a record holding a list of records;
each reproduces only with the full type (`toolSchemaToJson` with one `ToolParameter`),
